# 2.3 按键消抖与输入处理

## 机械按键为什么会抖

机械按键按下/松开时，金属弹片不会一次就接通，而是在电平之间**弹跳几次**，持续约 **5~20ms**。如果直接采样，一次按下会被 FPGA 当成几十次触发——流水灯、计数就会乱跳。

![按键抖动波形](../../../assets/phase2/key-jitter.svg)

## 计数消抖算法

思路：不要一看到电平变化就采纳，而是要求新电平**连续稳定保持一段时间**（约 20ms）才算数。

`debounce.v` 的核心状态：

- 若 `key_in == key_out`：输入和当前稳定输出一致，说明抖动回到原态，计数器清零。
- 若不一致但还没保持够：计数器累加。
- 若计到满 `HOLD_CNT`：说明输入真的稳定变了，采纳 `key_out <= key_in`。

计数窗口：

- 50MHz、20ms → `50,000,000 × 0.02 = 1,000,000` 个时钟。
- 位宽 `ceil(log2(1,000,000)) = 20 bit`（2^20=1,048,576）。

![消抖计数窗口](../../../assets/phase2/debounce-window.svg)

`tb_debounce.v` 故意制造一段快速来回跳变的抖动波形，再稳定保持，断言 `key_out` 在整个按下过程中**只翻转一次**。

## 亚稳态：比抖动更深的问题

异步输入（按键、其他时钟域的信号）如果正好在触发器的**建立/保持时间窗**内变化，触发器输出会进入**亚稳态**——既不是确定的 0 也不是 1，要过一段时间才收敛。若这个不确定值直接传播到后续逻辑，可能让状态机跳错状态、采样出错。

## 单 bit 两级触发器同步

对单 bit 异步输入，标准做法是**两级触发器同步**：

```verilog
always @(posedge clk or negedge rst_n) begin
    if (!rst_n) begin q1<=0; q2<=0; end
    else begin q1<=async_in; q2<=q1; end
end
assign sync_out = q2;
```

第一级 `q1` 可能亚稳，但我们**等一拍**让它收敛，再由第二级 `q2` 采样。这样亚稳态被局限在第一级，传不到后级。`tb_sync_2ff.v` 注入 `1'bx` 模拟亚稳态，验证两拍后输出稳定跟随。

![亚稳态与两级同步](../../../assets/phase2/metastability-2ff.svg)

> 两级同步只适用于**单 bit**控制信号；多 bit 总线跨时钟域必须用握手或异步 FIFO，不能简单打两拍（见阶段 4）。

## 综合实例：按一下切换 LED

`key_toggle.v` 把上面两块拼起来：

```
原始按键 → debounce 消抖 → 打一拍检测下降沿 → led 翻转
```

按下一次（消抖后）产生一个下降沿脉冲，`led <= ~led`，实现"按一下亮、再按一下灭"。`tb_key_toggle.v` 模拟带抖动的一次按下，断言 led 恰好翻转一次。

## 关键计算小结

- 消抖窗口 = `CLK_FREQ_HZ × HOLD_MS / 1000`，50MHz×20ms=1,000,000。
- 计数器位宽 20 bit。
- 两级同步针对单 bit；异步总线需专用跨域方案。
