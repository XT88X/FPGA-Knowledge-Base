# 5.3 硬件加速设计

到这里你已经能在 FPGA 上跑一颗软核 CPU 了。但 CPU 再快也是"串行"的——它一个周期只做一件事。这一节回答一个关键问题：**哪些活应该交给 CPU 跑程序，哪些活应该单独搭一块硬件去加速？** 这就是"软硬件协同设计"。

## 5.3.1 软硬件协同设计：先 profile，再划分

真实的 FPGA 系统不是"全硬件"也不是"全软件"，而是一颗软核 CPU 跑控制流，旁边挂着一块专门算数据的加速电路。怎么划分？标准流程是：

1. **先在 CPU 上把整个算法用 C 跑通**（哪怕慢）；
2. **profile（性能剖析）**：找出热点——到底是哪一段循环吃掉了 90% 的时间；
3. **软硬件划分**：
   - **控制密集、分支多、不规则**的部分（解析协议、状态机、错误处理）→ 留给 CPU；
   - **数据密集、规则、重复、可并行**的部分（乘加、滤波、卷积、矩阵乘）→ 做成硬件加速器；
4. 两者通过**内存映射寄存器 / AXI-Stream** 交换数据。

> 经验法则：一段代码里"for 循环体很小、循环次数很多、每次做的事几乎一样"——它就是硬件加速的绝佳候选。反过来，充满 if-else 和随机分支的代码，硬加速反而比 CPU 还慢。

## 5.3.2 硬件加速原理：并行、流水线、数据复用

CPU 和 FPGA 算同一件事，差距来自三个手段：

- **空间并行（展开）**：CPU 用 1 个乘法器依次算 4 次；FPGA 直接例化 4 个乘法器，一拍同时算 4 个乘积，再用加法树求和。这是"用面积换时间"，见 `ch3_serial_vs_parallel.svg`。
- **时间流水线（分级）**：把一条长组合路径（乘完再加）切成几级、每级插寄存器。这样每一级都短，时钟频率能拉高；流水线填满后**每拍都能流出一个结果**。延迟变大了，但吞吐上去了，见 `ch3_pipeline_space_time.svg`。
- **数据级复用**：同一块数据在片上被反复使用，而不是每次都从 DRAM 搬。配合双缓冲（一个缓冲算、另一个缓冲被 DMA 填充）把搬运和计算重叠起来。

**FPGA vs CPU 的频率/资源现实**：CPU 主频动辄 GHz，但一个周期只做一件事；FPGA 往往只有几十~上百 MHz，但一个周期里几十上百个乘法器同时在算。加速比不是靠"跑得更快"，而是靠"同一拍做得更多"。

## 5.3.3 接口：valid/ready 流式握手与 AXI-Stream

加速器和外界怎么传数据？工业界用 **AXI-Stream**：上游抬 `valid` 表示"数据准备好了"，下游抬 `ready` 表示"我能收"，**两个信号同时为高的那一拍，数据才算被接收**。下游忙时把 `ready` 拉低（背压 backpressure），上游必须保持数据不变。时序见 `ch3_valid_ready.svg`。

本仓库 `ch3_vec_mac_accel.v` 用的就是这种简化握手（不是完整 AXI4-Stream，只取 valid/ready + 数据/last/keep 的核心思想）。

## 5.3.4 第一个加速器：向量点积（乘加）

`code/phase5/ch3_vec_mac_accel.v` 计算 `result = Σ a[i]*b[i]`：

- **并行度 P=4**：每个输入拍送入 4 对 (a,b)，内部 4 个乘法器并行；
- **keep 掩码**：向量长度 N 不是 4 的倍数时，最后一拍用 `s_keep[3:0]` 屏蔽无效车道，天然支持任意长度；
- **2 级流水线**：乘级寄存 + 累加级寄存；
- **last 排空**：`s_last=1` 标记向量结束，流水线排空后在主通道吐出最终点积，累加器自动清零。

`ch3_tb_vec_mac.v` 做了四件事：①用整数循环算出软件 golden（N=10，结果 440）；②喂入非整除长度的向量；③结果吐出后故意延迟 `m_ready` 验证背压；④再跑一条短向量（结果 25）证明累加器被正确清零、没有串扰。

第二个例子 `ch3_fir_accel.v` 是**转置结构 FIR 滤波器**：`y[n]=Σ c[k]·x[n-k]`。它把寄存器放在加法反馈链上，关键路径短、易跑高频，是 DSP 里流水线分级的经典形态。`ch3_tb_fir_accel.v` 用全 1 系数（4 点滑动平均），对输入 `1..6` 期望输出 `1,3,6,10,14,18`。

## 5.3.5 性能怎么估：周期数模型（分析估算，非实测）

`ch3_sw_ref.c` 给出了纸面估算模型（**明确标注：这是分析估算，不是板上实测**）：

- 纯软件：`T_sw ≈ N × I_sw`（无硬件乘法时，一个元素约 20 条指令）；
- 硬件：`T_hw ≈ ceil(N/P) + 2`（每拍 P 个元素 + 流水线排空 2 拍）；
- 理想加速比 ≈ `P × I_sw`（N 很大时）。

代入 P=4、I_sw=20、N=1024：`T_sw≈20480` 周期，`T_hw≈258` 周期，**理论上界约 79 倍**。但这只是上界——真实加速比受内存带宽、DMA 起止开销、FPGA 实际 fmax 限制。`ch3_roofline.svg` 画的 Roofline 模型说的就是：实际性能 = min(计算峰值, 带宽峰值)，数据复用不够时加速器在"空转"。

> 如实声明：以上周期数是课堂级数量估算，本仓库环境只做行为仿真与结构校验，**未在 Vivado 综合、未上板测速**。真实加速比请在板上用计数器/profiling 实测。

## 5.3.6 可选：Vitis HLS（用 C 直接生成硬件）

手写 Verilog 加速器门槛高。AMD 的 **Vitis HLS** 能把 C/C++ 函数综合成 Verilog 硬件，用 `#pragma HLS pipeline/unroll/dataflow` 引导并行与流水。这是**可选进阶**，不是本仓库必需：

- AMD Vitis HLS 产品页：<https://www.amd.com/en/products/software/adaptive-socs-and-fpgas/vitis/vitis-hls.html>（访问于 2026-10）
- Vitis HLS 用户指南 UG1399（PDF）：<https://www.xilinx.com/support/documents/sw_manuals/xilinx2022_2/ug1399-vitis-hls.pdf>（访问于 2026-10）

> 学习路径建议：先手写本节的向量 MAC 理解"并行/流水/握手"到底在干嘛，再用 HLS 自动生成时才看得懂它在做什么、知道怎么调 pragma。
